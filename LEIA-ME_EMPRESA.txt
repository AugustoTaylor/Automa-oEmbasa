EMBASA PEDIDOS SAP - GUIA ÚNICO DE USO E PUBLICAÇÃO
Versão: 1.8.10
Atualizado em: 29/10/2026

1. O QUE O USUÁRIO FINAL DEVE ABRIR
O atalho do usuário deve apontar para:
N:\DF\FAFT\documentos\Gerir Tesouraria\Outros recebíveis\Serviços técnicos\Geracao Boletos Automaticos\EmbasaPedidosSAP\EmbasaPedidosSAP.exe

Antes de abrir:
- SAP GUI aberto.
- Usuário logado no ambiente correto.
- Sessão SAP pronta para automação.

2. O QUE DEVE EXISTIR NA PASTA DA REDE
Dentro da pasta EmbasaPedidosSAP devem existir, no mínimo:
- EmbasaPedidosSAP.exe
- _internal
- embasa_settings.json
- LEIA-ME_EMPRESA.txt
- VERSAO.txt

Não copie apenas o .exe. O build é onedir e precisa da pasta inteira.

3. CACHE COMPARTILHADO DO SETOR
O sistema usa o arquivo:
dados_compartilhados\cache\cliente_cache.json

Esse cache guarda dados fixos reutilizáveis do XD03:
- CPF/CNPJ limpo.
- Código do cliente SAP.
- Nome do cliente.
- Tipo de documento.
- Setores/tipos suportados.

A pasta é criada automaticamente na primeira execução. Ela não deve ser apagada ao publicar nova versão.
O script publicar_rede.ps1 preserva dados_compartilhados durante a cópia para a rede.

4. LOGIN, CADASTRO E MODELOS DE SALDO
Os dados compartilhados abaixo ficam fora do build e são preservados nas atualizações:
- dados_compartilhados\autenticacao\usuarios.json
- dados_compartilhados\saldo_contas\modelos.json

O arquivo de usuários não contém senhas legíveis. Ele guarda somente hash PBKDF2-SHA256, salt e tokens protegidos.
A opção "Lembrar senha" grava no computador do usuário apenas um token criptografado pela proteção de dados do Windows.
Não copie, edite manualmente nem apague esses arquivos durante uma atualização.

Na primeira utilização, o funcionário deve escolher Cadastrar e informar uma matrícula de 4 a 7 caracteres e uma senha com ao menos 8 caracteres, letras e números.
O cadastro não abre o sistema automaticamente: depois de criar o acesso, o funcionário deve entrar pela tela de login. A opção "Lembrar senha" é aplicada somente nesse login.
Nas utilizações seguintes, o sistema faz o check-in na base compartilhada. Se a pasta da rede estiver indisponível, o acesso é bloqueado em vez de criar um cadastro local paralelo.

Na tela Saldo de contas, a planilha é detectada e apresentada para confirmação. Os modelos salvos podem alterar, desativar ou excluir até mesmo as contas padrão. O número 11311000 continua obrigatoriamente desativado devido ao timeout conhecido no SAP.

4.1. REAPROVEITAMENTO DO ÚLTIMO BOL
O sistema guarda por data de execução o último BOL usado no arquivo compartilhado:
dados_compartilhados\f110\ultimo_bol.json

Exemplo: se o último concluído foi BOL08, a próxima F110 começa verificando diretamente BOL09, sem consultar novamente BOL01 até BOL08. O candidato memorizado sempre é validado no SAP antes do preenchimento. Se outra execução já tiver ocupado BOL09, o sistema segue para BOL10.

O arquivo também registra reservas temporárias para reduzir colisões entre computadores. Uma tentativa interrompida é validada novamente e pode ser reutilizada se continuar livre. A memória é separada por dia e o histórico compartilhado é usado para iniciar o arquivo quando já existem boletos concluídos.

Não edite nem apague esse arquivo durante o expediente. Ele fica dentro de dados_compartilhados e é preservado pelo processo de atualização.

5. FALE CONOSCO
O formulário envia os pedidos automaticamente para faft@embasa.ba.gov.br.
O usuário não precisa ter Outlook aberto nem uma conta de e-mail configurada no computador.

O envio padrão usa uma conexão TLS direta com o servidor de entrada corporativo, pela porta 25. O destinatário é fixo no backend e não pode ser alterado pela interface nem pelo arquivo embasa_settings.json.
Não grave senha de e-mail no arquivo de configuração. O modo padrão não usa usuário nem senha.

Se a infraestrutura de e-mail da EMBASA mudar, a equipe de TI deve atualizar somente os campos smtp_host, smtp_port e smtp_use_tls da seção support em embasa_settings.json.

6. TEMPO DE DEMONSTRAÇÃO DAS AÇÕES
No arquivo embasa_settings.json existe a seção:

"timing": {
  "action_delay_seconds": 0,
  "max_action_delay_seconds": 30
}

Uso:
- 0 = velocidade normal, sem atraso artificial.
- 5 = após cada ação principal do SAP, aguarda até 5 segundos para facilitar demonstração.

Depois de alterar esse valor, feche e abra o sistema novamente.
Não use esse atraso em produção normal, apenas para teste, apresentação ou acompanhamento visual.

7. COMO GERAR UMA NOVA VERSÃO
No computador de manutenção, dentro da pasta do código-fonte, rode:

powershell -ExecutionPolicy Bypass -File .\build_empresarial.ps1

Esse comando recria a .venv local, instala as dependências e gera:
dist\EmbasaPedidosSAP

8. COMO PUBLICAR NA REDE
Depois do build, rode:

powershell -ExecutionPolicy Bypass -File .\publicar_rede.ps1

O script já usa como destino padrão:
N:\DF\FAFT\documentos\Gerir Tesouraria\Outros recebíveis\Serviços técnicos\Geracao Boletos Automaticos\EmbasaPedidosSAP

Se precisar publicar em outro local, informe o destino manualmente:

powershell -ExecutionPolicy Bypass -File .\publicar_rede.ps1 -DestinoRede "CAMINHO_DA_REDE"

9. SOBRE EXECUTAR PELA REDE
Quando aberto pela unidade N:, o sistema copia automaticamente a pasta do aplicativo para:
%LOCALAPPDATA%\EMBASA\Runtime

Depois ele relança o executável dessa cópia local.
Isso evita falhas do pythonnet/.NET ao carregar DLL diretamente pela rede.
Na primeira abertura após uma atualização pode demorar alguns segundos a mais.

Mesmo rodando pela cópia local, o cache compartilhado continua apontando para a pasta original da rede.

10. SE DER ERRO ANTES DA INTERFACE ABRIR
Verifique o log:
%TEMP%\EMBASA\startup.log

Erros comuns:
- SAP não está aberto/logado.
- Pasta da rede incompleta, faltando _internal.
- Usuário abriu um .exe copiado sozinho, fora da pasta onedir.
- Microsoft Edge WebView2 Runtime ausente.
- .NET Desktop Runtime ausente.

11. TESTE RÁPIDO APÓS PUBLICAR
- Abrir o SAP e fazer login.
- Abrir o atalho do EmbasaPedidosSAP.exe pela rede.
- Cadastrar uma matrícula de teste ou entrar com usuário existente.
- Fechar e abrir novamente para confirmar o check-in com "Lembrar senha".
- Confirmar que a interface abriu.
- Fazer um teste com dados reais controlados.
- Repetir o mesmo CPF/CNPJ para confirmar que o cliente foi recuperado do cache.
- Verificar se o progresso em tempo real, cancelamento e logs aparecem corretamente.

12. OBSERVAÇÃO
Não é necessário instalar Python, VS Code ou Git nos computadores dos usuários finais.
Python só é necessário no computador de manutenção para gerar novo build.
